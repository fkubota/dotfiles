# 知見ファイルのフォーマット詳細

知見ファイルを**新規作成**するとき、または既存ファイルを**大きく再構成**するときに参照する。
既存ファイルへの追記は、そのファイルの既存フォーマットに従えばよい。

## ユニットナレッジ（ビジネスロジック系）

```markdown
# {ドメイン名}

> 種別: unit knowledge

## 概要
（このドメインの簡潔な説明）

## 詳細
（調査で得た知見。コード構造、DB設計、ビジネスロジックなど）

## 関連
- [[関連ドメインのファイル名]]
- ソースコード: パス（GitHub URL があれば付ける）
- ドキュメント: パス
```

## クロスナレッジ

```markdown
# {横断テーマ名}

> 種別: cross knowledge

## 概要
（このテーマが束ねる範囲の説明）

## 全体像
（複数トピックを横断した合成。フロー・関係・対比など）

## 構成ページ
- [[unit-knowledge-a]] — 一言説明
- [[unit-knowledge-b]] — 一言説明

## 横断的知見
（複数ソースを突き合わせて見えてきた気づき。時間とともに育つ箇条書き）
- ...

## 未解決の問い
（まだ答えが出ていない疑問・要検証事項。次回以降の調査の起点）
- [ ] ...
```

## DB・テーブル系（`knowledge/database/`）

```markdown
# {テーブル名 or ドメイン名}

> 種別: unit knowledge

## テーブル概要
（テーブルの用途・役割）

## 主要カラム
| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid | PK |
| ... | ... | ... |

## テーブル間リレーション
- `{テーブル名}.{カラム}` → `{参照テーブル}.id`（説明）

## よく使うSQL
```sql
-- 説明
SELECT ...;
```

## 調査メモ
（気づいたこと、注意点など）
```
