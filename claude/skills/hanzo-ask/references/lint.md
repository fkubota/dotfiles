# Lint（知見の健全性チェック）の詳細手順

`/hanzo-ask --lint`（または「点検して」「健全性チェック」）で起動する全件点検モードの手順。
引数にファイル名を付けると（`--lint out-ratio.md`）そのファイルのみを対象にする。

「コード参照」「最終確認日」の定義は SKILL.md 本体の「自発 Lint」セクションと共通。

## 点検項目

1. **陳腐化**: **最終確認日**（`max(mtime, .lint-verified の確認日)`）が**1ヶ月以上前 かつ コード参照を含む**ファイルを一覧化
2. **コード乖離**: ファイル内のソースパス（`web/app/...rb` 等）や GitHub URL の `{path}` を抽出し、現行 foodies に存在するかを確認（重いので対象ファイルを絞って実行）
3. **孤立ページ**: どの知見ファイルからも `[[]]` でリンクされていないファイルを検出
4. **INDEX 乖離**: `INDEX.md` に載っているが実体がない／実体はあるが INDEX 未登録のファイルを検出
5. **矛盾**: 同一トピックで食い違う記述がないか（横断的に確認）

## 出力と修正

- 結果は項目ごとにレポートする（結論を先に：「N 件の要対応を検出」）
- **修正は必ず承認を取ってから**行う。Lint は検出とレポートまでが基本で、勝手に書き換えない
- **コード乖離なし（クリーン）と確認したファイルは `.lint-verified` に確認日（今日）を記録/更新する**。これにより mtime が古くても次回から自発警告されなくなる
- 全件点検を実行したら `.lint-state` の `last_full_scan` を今日の日付に更新する（自発サマリと共有）
